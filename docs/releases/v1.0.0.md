# GitHub Copilot Bridge 1.0.0

## Release notes

A full-page Copilot experience for DeepSeek Harness, with automatic provider setup and model visibility that follows your sign-in state.

### Highlights

- **Dedicated sidebar page:** open GitHub Copilot for Account and Models, with theme-aware artwork and English/Chinese UI.
- **Automatic setup:** sign in with GitHub or GitHub Enterprise and the plugin creates the native Copilot provider only if absent. Existing configuration is preserved. Setup problems do not discard your sign-in; retry without repeating OAuth.
- **Account usage:** view credit usage, reset time and exact values, with manual refresh.
- **Model management:** search, hide and restore models with immediate-save eye toggles. See available context/input metadata, credit prices, discounts and retiring-model warnings.
- **Immediate catalog:** manage models after provider setup without sending a chat request. A labelled provider catalog is used until the account-specific catalog is known; it does not guarantee account entitlement.
- **Reliable sign-out:** Copilot models disappear from pickers, including cached/in-flight listings, while provider configuration is retained. Models return on sign-in.

### Upgrade notes

- **Breaking:** `/copilot-login`, `/copilot-status` and `/copilot-logout` have been removed. Use **GitHub Copilot → Account** from the sidebar.
- Authentication and Enterprise host controls have moved out of Settings. There is also an **Open GitHub Copilot** shortcut in the installed plugin page.
- Restart Harness after updating to reload client registrations and package metadata.
- Hidden-model choices reset on sign-out and completed sign-in. Existing credentials and provider configuration need no migration.
- Requires Node.js **24+** for package tooling. Integration verified with **Harness 0.2.2-rc.5**.

## Manual release checklist (maintainer only; not release-note copy)

Preparation does not create a tag, publish a GitHub release or publish to npm.

1. Review and merge the `release/v1.0.0` preparation PR into `main`.
2. Switch to `main` and update with `git pull --ff-only`. Confirm `package.json` and both root version fields in `package-lock.json` are `1.0.0`.
3. Run `npm ci` and `npm run check`. The build must report `dsh-copilot-bridge v1.0.0`; there should be no tracked changes afterward.
4. Optionally rerun the installed adapter integration check documented in `README.md`. These tests use in-memory credentials/settings and do not modify the desktop profile.
5. In Harness, smoke-test the updated plugin: artwork in both themes; sign-in; provider setup; Models before any chat; hide/restore; sign-out removes picker entries; sign-in restores them. Do not copy real credentials into release artifacts.
6. Inspect `npm pack --dry-run`. Confirm the package includes `lib/index.js`, `lib/client.js`, the SVG icon, both locales, the patch, license, README and changelog, but no credentials or development fixtures.
7. In GitHub **Releases → Draft a new release**, create tag **`v1.0.0`** targeting the merged release commit on **`main`**. Title: **`v1.0.0`**. Copy only the **Release notes** section above. Publish manually when ready.
8. If you also distribute through npm, publish manually from the verified `main` checkout using `npm publish --access public`. This is separate from the GitHub release; do not run it if npm distribution is not intended.

### Rollback

Reinstall the previous published release, `v0.1.0`, and restart Harness. Do not reuse the `v1.0.0` tag for a different build; publish a new patch version for fixes. An automatically created provider profile is retained and can be removed manually in Harness if no longer wanted. No credential migration is performed by this release.
