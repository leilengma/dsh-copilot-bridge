# GitHub Copilot Bridge 1.0.2

## Release notes

### Install without unnecessary dependency-build approval

- The prepared npm package and release tarball now bundle the public Copilot transports used by the bridge instead of installing pi-ai's full SDK dependency tree.
- Fresh production installs no longer pull in unused `@google/genai` / `protobufjs` build scripts. pnpm's strict build policy is preserved: no global approval, `allowBuilds` entry or security bypass is needed for those dependencies.
- Anthropic Messages, OpenAI Responses and OpenAI Completions remain supported. Bundled third-party licenses are included in `THIRD_PARTY_NOTICES.txt`.
- Repository package metadata, lockfile and bundled client now consistently report **1.0.2**.

### Upgrade and marketplace notes

- Update to **dsh-copilot-bridge 1.0.2** after it is published, then restart Harness. Existing bridge sign-in, hidden models and pins are unchanged by this packaging fix.
- npm distribution is discovered by the marketplace through the package's existing `repository` mapping. A separate version announcement is not required.
- The draft marketplace change adds a prebuilt fallback at `https://github.com/leilengma/dsh-copilot-bridge/releases/latest/download/dsh-copilot-bridge.tgz`. Every future latest release must include that exact, version-free asset name. Do not merge that change until the GitHub release is public and this URL works.
- Profiles containing other plugins or earlier undecided builds may still prompt about those packages. This fix does not approve scripts or clear profile-wide pending decisions. Development/Git-source preparation is not the same as a prepared production-package install.
- Tooling requires Node.js **24+**. Installed-runtime fixture checks target Harness **0.2.2-rc.5**. No real desktop profile or account is changed by those checks.

## Maintainer checklist (not public release-note copy)

Preparation includes a release PR, tested tarball/checksums, a **draft** GitHub release and a **draft** marketplace fallback PR. Nothing is published to npm and no public tag/release is created during preparation.

1. Review and merge `release/v1.0.2` into `main`. Update the checkout using `git switch main && git pull --ff-only`. Confirm `package.json` and both root lockfile version fields are `1.0.2`.
2. Verify `npm ci`, `npm run check`, `npm audit`, `npm pack --dry-run` and both installed Harness checks documented in `README.md`. Inspect all 11 package files, including `THIRD_PARTY_NOTICES.txt`; no credentials, test fixtures or `node_modules` should be shipped.
3. Verify the prepared tarball in a fresh temporary pnpm consumer with `autoInstallPeers: false`, `strictDepBuilds: true` and empty `allowBuilds`. It should install only five packages and require no dependency-script approval. Run the packed-transport fixture probe against that installed package, with only host-provided peer imports supplied by Harness.
4. A physical desktop installation and live provider request remain manual smoke tests, not claims made by these fixture checks. If desired, test install/restart, sign-in, model refresh, pin/hide/restore and an Opus default-effort chat. A live chat may consume account quota.
5. **Publish to npm yourself:** `npm publish /absolute/path/to/dsh-copilot-bridge-1.0.2.tgz --access public` using the verified prepared artifact, or run `npm publish --access public` from the verified merged checkout. Publish only once. Confirm `npm view dsh-copilot-bridge@1.0.2 version dist.integrity repository.url` and the registry's latest dist-tag; registry mirrors/caches may take time to catch up.
6. In the draft GitHub release, ensure tag **`v1.0.2`** targets the merged release commit on **`main`** (not the older main commit). Copy only the **Release notes** section above. Verify attached `dsh-copilot-bridge-1.0.2.tgz`, identical version-free `dsh-copilot-bridge.tgz`, and `SHA256SUMS.txt`. Publish the release as latest after the npm release is available.
7. Check `https://github.com/leilengma/dsh-copilot-bridge/releases/latest/download/dsh-copilot-bridge.tgz` downloads the 1.0.2 package and matches the checksum. Only then mark the marketplace fallback PR ready for review/merge. Do not merge a link to a draft or nonexistent public asset. Retain the same version-free asset name on future latest releases.
8. The catalog entry's URL, name, category and bilingual description remain unchanged; only the optional `tarball` fallback is added. Do not edit generated marketplace READMEs. Existing installations are not guaranteed to upgrade automatically.

### Rollback

Reinstall `1.0.1` and restart Harness; this release has no credential/configuration migration. That restores the previous external pi-ai dependency graph and may require approval for its transitive scripts. Do not weaken pnpm policy merely to roll back. Never overwrite an existing npm version or reuse a tag for different content. If an install or packaging defect is found, publish a new patch version; an older GitHub latest release must also supply the stable asset before the marketplace fallback can use it.
